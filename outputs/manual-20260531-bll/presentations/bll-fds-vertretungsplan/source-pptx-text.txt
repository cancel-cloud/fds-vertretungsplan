--- SLIDE 9 ---
KAPITEL 3  ·  KERNLOGIK
Matching: Ist diese Vertretung für mich relevant?
Vier Prüfschritte pro Vertretung
1
Wochentag
Datum der Vertretung → Wochentag des Stundenplan-Eintrags
2
Wochenmodus
Jede Woche / gerade / ungerade – passt zur Kalenderwoche?
3
Stunden überlappen sich
Stundenblock der Vertretung schneidet den eigenen Stundenblock?
4
Fach, Lehrer oder Raum
Mindestens eines stimmt ausreichend überein
Pseudocode
function istRelevant(v, e):
  // v = Vertretung,  e = Stundenplan-Eintrag
 
  if v.wochentag != e.wochentag:
      return false
  if not wochenmodusPasst(v, e):
      return false
  if not stundenUeberlappen(v, e):
      return false
 
  return fachLehrerRaumPasst(v, e)
Diese Funktion läuft auch im Hintergrund-Dispatch – sie entscheidet, ob jemand überhaupt eine Push-Benachrichtigung bekommt.

--- SLIDE 11 ---
KAPITEL 3  ·  QUALITÄT
Sicherheit & Datenschutz – als Querschnittsthema
Authentifizierung
Geschützte Bereiche nur für angemeldete Nutzer; Middleware + serverseitige Guards prüfen jeden Request.
Browser-Härtung
Content Security Policy, CSRF-Schutz auf mutierenden Requests, HTTPS in Produktion verpflichtend.
Abuse-Schutz
Rate-Limit auf Registrierung und Login (IP + E-Mail), Begrenzung externer Requests gegen WebUntis.
Datenschutz technisch
Minimale Datenhaltung, gehashte Passwörter (bcrypt), klare Rollentrennung, Pflichtseiten Impressum/Datenschutz.
Sicherheit war kein Zusatzblock am Ende, sondern Teil jeder Architekturentscheidung.

--- SLIDE 13 ---
KAPITEL 5  ·  REFLEXION
Drei zentrale Herausforderungen
#1  Schnittstelle ohne Doku
PROBLEM
WebUntis bietet keine offene API für diesen Anwendungsfall.
LÖSUNG
Systematische Netzwerkanalyse, eigenes Datenmodell, Server-Proxy mit Validierung und Cache.
#2  Push ohne Spam
PROBLEM
Naive Lösung würde alle 15 Minuten dieselben Inhalte verschicken.
LÖSUNG
Eigene Delta-Logik mit Fingerprints; drei Aktionen send/skip/resolve, persistenter Zustand.
#3  Architektur-Wachstum
PROBLEM
V1 und V2 zerbrachen unter neuen Anforderungen wie Login und Personalisierung.
LÖSUNG
Bewusster Neustart als V3 mit klarer Schichten-Trennung – Datenmodell zuerst.
